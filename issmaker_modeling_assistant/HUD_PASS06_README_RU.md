# ISSMAKER HUD Evidence Lab — Pass 06

Сборка **экспериментальная**. Реальные Blender GUI-тесты и согласованность оформления НЕ ЗАЯВЛЕНЫ как успешно пройденные разработчиком.

## Как запустить
1. Установите ZIP как обновление ISSMAKER в Blender 4.5.5 LTS. Предварительно сохраните свой `.blend`.
2. Откройте **3D Viewport → N → ISSMAKER → Рабочая область → Диагностика**.
3. Нажмите **NEW TEST · создать всё для HUD**. Это создаёт **новую отдельную сцену** с шестью объектами для испытаний; старую сцену не очищает и не меняет.
4. Для каждого сценария нажмите **Подготовить объект теста**, запустите нужный HUD вручную, затем **Снимок через 4 секунды**. За эти 4 секунды откройте нужное окно. После снимка вернитесь в диагностику.
5. Добавьте комментарий и поставьте **PASS / FAIL / BLOCKED**. PASS требует реального снимка. Невыполненные сценарии останутся `NOT_TESTED`.
6. Нажмите **Проверить размещение HUD** для снимка реальных прямоугольников окон, зарегистрированных в Blender. «0 возможных пересечений» при отсутствии открытых HUD не означает успешное испытание.
7. Нажмите **СОБРАТЬ EVIDENCE ZIP**. Полный путь к ZIP копируется в буфер. Отправьте этот архив для независимого разбора.
8. **Вернуться в рабочую сцену** возвращает оригинал без удаления диагностической сцены. Сначала сохраните ZIP, иначе при закрытии Blender несохранённые результаты могут потеряться.

## Что создаёт NEW TEST
- `UV_WALL_PATH`: редактируемый полилинейный путь, без граней, с несколькими высотами Z.
- `BRICK_FACE`: выделяемая плоская Mesh-грань с UV.
- `DWOS_WALL`: демонстрационная стенка из восьми граней с центральным проёмом. Только UI-фигура, НЕ эталон генерации DWOS.
- `COLLISION_SHELLS`: единый Mesh из двух закрытых пересекающихся оболочек.
- `GENERAL_MESH`, `UV_CHECK`: Mesh для материалов, UV, общих HUD.

## Ограничения достоверности
- Автоматически проверяется создание тестовых объектов и снимки состояний API. В Blender GUI **клики и движения мыши пользователь выполняет сам**; генерации поддельных input-событий нет.
- 1K/2K/4K означают 1920×1080, 2560×1440, 3840×2160. Для соответствующего PASS проверяются реальные размеры **окна Blender**, а не угадывается разрешение физического монитора. Данные о масштабировании ОС могут потребовать отдельного свидетельства.
- UI-инструменты запускаются через их оригинальные кнопки. Контракт построения геометрии или UV этим тестом не подтверждается.
- Отрицательные результаты/снимки важнее счётчиков PASS. Один FAIL или BLOCKED означает, что релиз нельзя считать полностью принятым.
- ZIP содержит скриншоты интерфейса, пути и системные метаданные; перед отправкой проверьте его на приватные данные.
- Тестовые объекты находятся в отдельной сцене, но при сохранении `.blend` сохранятся вместе с ней, пока не удалены пользователем.
